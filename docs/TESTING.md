# Build 4 testing and release gate

## Automated release command

From the repository root:

```bash
npm run check
```

This runs every Node test, builds the exact Vite production bundle and injects the final hashed asset list into the service worker. A source-test pass without the production build is not a release pass.

## Product-flow scenarios

### New child

1. Create/select a profile.
2. Confirm the shell contains only Our Planet, My Keys, My Work and Enter a Key.
3. Confirm Our Planet shows exactly four active destinations and no future cards.
4. Enter each destination and begin a real interaction without an introduction page.
5. Confirm the first useful object appears within five seconds on the target iPad/network profile.
6. Return to Our Planet using the same logical control.
7. Open My Work and recognise its three views.
8. Enter an Activity key and arrive directly after digit four.

### Returning child

1. Use the one Continue invitation from Our Planet.
2. Open the most recent Key Activity from My Keys.
3. Reopen and revise saved work from My Work.
4. Switch destinations and confirm common back/save/help language.
5. Refresh and confirm draft/save status remains understandable.

### Teacher

1. Enter `8584`.
2. Confirm favourites/recent records appear before a destination is selected.
3. Search for a Climate concept and filter each of the four destinations.
4. Display a code, return to children’s view and open Board View.
5. Complete the journey in under 30 seconds on the target classroom device.
6. Perform a real document refresh at `#/maintenance`; confirm adult access closes.

### Shared iPad

1. Create two profiles with different scaffold/accessibility settings.
2. Give each a different key and save different work.
3. Switch repeatedly; confirm keys, work, settings, recent destination and library view never cross profiles.
4. Refresh and repeat.

## Climate content checks

### Patterns

- generated one-day event is visibly labelled fictional
- station monthly pattern remains sourced with period/units
- one day, week, year and multi-year labels describe different evidence scales
- graph toggles do not remove essential accessible descriptions
- equal yearly totals remain equal after seasonality changes
- Northern/Southern Hemisphere examples do not assume UK seasons everywhere

### Climate Map

- shared `AtlasMap` mounts and destroys cleanly
- globe/flat controls and keyboard interaction remain functional
- five climate-zone choices use patterns as well as colour
- zone copy states that boundaries are broad, not walls
- latitude explanation includes oceans, winds, altitude and local geography
- UK/Gambia comparison uses Heathrow/Yundum station titles and periods
- links return to established UK/Gambia Atlas records

### Experiment

- temperature range is −40°C to 40°C with 1°C step buttons
- rainfall range is 0–4,000 mm with 50 mm step buttons
- units remain visible at every setting
- keyboard, tap-to-step, undo and reset do not require precise dragging
- scene changes gradually and remains labelled simplified
- candidate biomes are plural possibilities
- biome habitat IDs exist in Living Things records
- organism claims remain needs/possibilities, not presence claims

### Change

- global warming is defined as a long-term global average pattern
- NASA baseline, period and selected-year simplification remain visible
- one hot/cold day is not treated as proof/disproof
- effects use may/could/depends on and retain uncertainty
- response records distinguish reducing causes and adapting
- no scenario gives a moral score, guaranteed future or child-only responsibility
- observed/known/inferred/predicted/uncertain text saves separately

## Climate provenance and validation

- every source has URL, publisher, title, retrieval date and use note
- every location has 12 temperatures, 12 rainfall/precipitation totals, units, coordinates, hemisphere, period/status and source IDs
- pinned Heathrow and Yundum arrays match the official displayed tables/transformation
- Yakutsk says `Source period not supplied`
- generated weather is `fictional`
- experiment/effect/response components are `simplified-model`
- station patterns and NASA strip are `sourced-rounded`
- saved mixed artefacts retain component-level labels
- unknown sources, missing units, invalid coordinates, hemisphere contradictions, missing months, reversed limits and duplicate IDs fail validation
- 2,000 seeded generator cases reproduce exactly and pass task validation

## Accessibility matrix

- touch and keyboard navigation for every destination/mode/tool
- range arrow keys plus ± alternatives
- visible focus at browser zoom and enlarged app text
- high contrast and forced colours
- graph/zone meaning without colour
- spoken instructions/data plus visual equivalent
- captions/replay for any audio
- reduced-motion mode
- screen-reader headings, landmarks, labels and figure descriptions
- no timed tasks or precision-drag dependency
- long source/location names without overlap

## Responsive/manual device matrix

Automated DOM/CSS contracts do not prove physical-device behaviour. Before declaring a hardware-certified release, record browser/OS and inspect:

| Context | Required journey |
|---|---|
| iPad Safari portrait | profile, home, all four destinations, key entry, climate sliders/graphs, My Work, Board View, print preview |
| iPad Safari landscape | same journey plus shared Atlas map, 8584 display and keyboard dismissal |
| iPad Home Screen | standalone safe areas, update, offline cold reopen after one online load |
| Classroom display | 8584 search/display/return, anonymous Board View, hide/reveal, reset |
| Desktop Safari/Chrome | keyboard, speech, voice recording where allowed, backup and print |
| Narrow 320 px fallback | four nav items, climate modes, long location/source text, no page overflow |
| Enlarged text/browser zoom | reflow without clipped maps, graphs, labels or nested scroll traps |

Physical iPad Safari, home-screen installation, real offline cold launch and printer output must be reported as manual limitations when that hardware is unavailable.
