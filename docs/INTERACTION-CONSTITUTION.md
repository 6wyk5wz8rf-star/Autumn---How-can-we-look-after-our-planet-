# Interaction Constitution

This constitution applies to Build 5 and every later build. A release cannot treat these rules as optional visual polish; they are product architecture.

1. **Four top-level child navigation areas only.** They are Our Planet, My Keys, My Work and Enter a Key.
2. **No new top-level destination buttons.** Completed curriculum environments live inside Our Planet.
3. **No dead future destinations.** Registered future places must not appear as disabled cards, locks, “coming soon” labels or empty controls.
4. **Destination entry must begin with interaction.** A child should reach a useful manipulable object without an introduction page, tutorial carousel or tool-grid gateway.
5. **No more than four primary modes per destination.** Specialist tools are disclosed contextually.
6. **One primary action per screen.** Save, print, help, reset, Board View and settings must not compete visually with the learning action.
7. **Use progressive disclosure.** Reveal representations, labels, variables and specialist controls when they become useful; never hide essential accessibility or unit information.
8. **Use Keep in My Work consistently.** Draft saving is quiet; meaningful saved outcomes share one phrase and one predictable versioning model.
9. **Use Show me consistently.** Help supplies one short demonstration, one modelled example, one immediate child action and a return to the unchanged task.
10. **Keys provide direction, not permission.** Every completed destination remains open; a key remembers and routes to a useful guided pathway.
11. **No assignment features.** Do not add deadlines, required completion, pass/fail, scores, rankings, surveillance or learner-task allocation.
12. **New builds must not increase cognitive load without removing something else.** Any new mode, control, label, panel or decision requires an explicit simplification elsewhere in the same flow.

## Release review

Before activating a new destination, test a new child, returning child, teacher and two-profile shared iPad journey. Review every new control against three questions:

- Does the child know where they are?
- Is the next useful action obvious?
- Can they return without losing work or context?

If any answer is unclear, the destination is not ready to activate.
